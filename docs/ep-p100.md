# P100 expert-parallel experiment

This branch contains an isolated true expert-parallel execution path developed for Qwen3-VL-30B-A3B on two NVIDIA P100 GPUs.

## Known-good implementation

- Branch: `ep-p100-concurrent`
- Implementation commit: `606d3cd955a3ddc34092aefa061b92141da87261`
- Hardware: 2x NVIDIA P100
- Model: Qwen3-VL-30B-A3B
- MoE topology: 128 experts, fixed 64/64 whole-expert ownership across GPU0 and GPU1

## What changed

The experiment preserves expert ID, routing-weight, and routed-slot ordering while assigning whole experts to a fixed GPU owner. The scheduler launches the GPU0 and GPU1 expert branches concurrently and joins once per MoE layer rather than serializing the two branches.

This is intentionally distinct from ordinary llama.cpp layer split or tensor split: the unit of placement is the whole routed expert.

## Validation

The implementation produced coherent model output and Nsight profiling confirmed real overlapping CUDA execution between the two P100s during the expert work.

## Initial result

Short-decode throughput improved from approximately:

- baseline: **28.7 tok/s**
- concurrent expert-parallel path: **31.4 tok/s**

That is about a **9.4% decode-throughput improvement** for the first working concurrent implementation.

## Scope

This result is a baseline for further expert-parallel optimization, not a claim that the current scheduler, placement, synchronization, or communication strategy is optimal.

The exact benchmark command and complete runtime configuration should be appended when recovered from the original benchmark session so future comparisons can reproduce this result exactly.
